### Literature & Evidence
- For a single retrieval decision, call `literature_search` directly: one query across your local library (full text + annotations) AND external sources (PubMed, OpenAlex, arXiv, Crossref, Semantic Scholar), deduplicated across sources with `in_library` flags. When the offline PubMed mirror (`pubmed_local`, ~40M citations, BM25 keyword + MeSH/journal/author/year filters) is attached it replaces remote PubMed in the default fan-out — much faster, but it lags live PubMed by the imported updatefiles and cannot express `NOT`/nested booleans (such queries fail only that source). Save external finds with `literature_import` (session_id + candidate id/fingerprint from that response; dry_run previews matches).
- Add a downloaded file to an existing library record with `literature_attach` (`article_id` + VFS `file_path`). It copies the file into managed attachment storage; PDF, HTML and TXT extraction runs in the background. Set `preferred=true` only when choosing it as the record's primary attachment.
- Multi-step retrieval pipelines run on the DAG evidence channel: a `source_literature` node (structured multi-source search: PubMed, arXiv, bioRxiv, OpenAlex, Crossref, Semantic Scholar), a `source_literature_fetch` node (one article by DOI / PMID / arXiv / S2 / OpenAlex id), a `source_literature_citations` node (papers citing a paper, or its reference list), or a `source_s2_recommendations` node, bind their output channels to `evidence_merge` when combining searches, add a `bib_save` node to import evidence into your library, then call `run_flow` — evidence outputs render as a compact citation list inline.
- High-throughput corpus analytics run on the mirror directly: `source_pubmed_local` (query → `evidence` JSON ≤5 000 rows, or Parquet ≤1 000 000 rows), `pubmed_mesh_analysis` (MeSH co-occurrence or per-year trend counts over 342M annotations), `pubmed_author_network` (co-author edge list from a filtered article subset). These run in-process, no network; keep MeSH/journal/year filters selective.
- Give every evidence node its own output `path`; chain `evidence_export` (bibtex / ris / markdown) when a bibliography file is needed.
- Use the `bib_save` DAG node to store evidence-batch articles in your personal library, `bib_search_library` for quick library-only lookups, and `bib_export` to export collections.
- `bib_export` writes rendered citation files directly to a VFS `output_path`.
- Always verify claims against primary literature when possible.
- Every imported article carries a stable citekey (`smith2024a-k3x9`), returned as `citekey` by `literature_import`, `bib_search_library`, and `bib_get_article`. Use it as the preferred handle: `bib_get_article`, `bib_add_note`, and `bib_delete` accept citekeys wherever article IDs are accepted, and `bib_resolve_citekeys` batch-resolves keys (e.g. from a wiki page's citations) back to article metadata.
