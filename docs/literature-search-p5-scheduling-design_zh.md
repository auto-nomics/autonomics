## 来源扫描与单轮检查

分别持久保存“每源扫描”和“本轮检查”，避免把单轮页数预算误当作整个时间窗口的终止条件。

- 每源扫描保存 UUID、策略、冻结目标、下一子窗口起点及是否完成。当前窗口的计划、游标和页面序号继续使用现有源状态。预算耗尽、服务重启或租约接管均继续同一窗口；只有扫描完成后才建立下一次目标。
- 每轮检查保存客户端已知 UUID、规则版本、所有者 epoch、开始/截止时间、规则副本、各源目标、请求/提交页数、已原子提交的记录数、新通知数、终止原因及实际窗口计划。完成后的记录只读。
- 各来源独立推进。一个来源权限失败或长期重试，不得阻止其他来源在后续检查中开始新的扫描。全局最后成功时间只在本轮所有来源成功时更新；它是检查成功时间，不是统一的上游更新时间水位。
- 有界重放来源保存实际遍历范围与检查时间，不产生虚构的更新水位。大结果集分页未尽时记录部分完成，不能显示“无新增”。

窗口子分段的下一起点必须由已经完成的子窗口推进并持久保存，不能每次从 `watermark - overlap` 重新计算。否则重叠 3 天、窗口 1 天的规则会永远扫描同一最早一天。全局水位可以保持最大值，每源扫描的下一子窗口起点仍须前移。

PubMed 沿用已实现的完整 UTC 日窗口，其冻结目标为最近完成的 UTC 日；界面须说明此策略的日期粒度与当前日延迟，不能宣称实时更新覆盖。Crossref 使用最近完成的 UTC 秒作为目标。OpenAlex 普通密钥、arXiv、S2，以及不能安全叠加原生索引日期约束的 Crossref 规则采用有界重放。来源更细时间语义的扩展须另行验证，不能通过未验证的字段或未来时间水位填补。

## 页面预算与原子提交

在发起供应商请求前持久预留一次页面尝试及对应整页记录额度。队列等待、限流冷却和供应商调用均计入本轮及每源期限。失败的页面尝试也消耗本轮页面预算；记录额度在成功页面事务中按实际提交数量结算；请求失败释放记录预留但不退还页面尝试额度。若响应因存储额度不足未能提交，不能把其结果数或通知数显示为已提交。

同一来源在一轮内至多有一个未结算页面；允许不同来源有界并发，并继续使用 `DiscoverySessions.execute_planned_page` 的共享许可和冷却。游标绑定页面大小，不能为凑剩余额度而悄悄改变下一页大小。预算设置必须能容纳至少一个完整源页面；不足以继续下一整页时结束本轮，检查点留待下一轮。

成功页面的通知、已见身份、源检查点、扫描推进和本轮计数在同一立即事务更新。源错误和重试时间也要与失败页面的预留结算一起保存。所有路径在提交前重新检查规则版本、所有者、epoch、租约及本轮仍处于执行态；旧请求不得在结束或取消后提交。

执行历史的载荷和条数纳入持久预算，禁止默默丢弃旧记录。预留请求时也预留终止状态与有界错误信息的空间，避免“额度已满”反而使本轮无法被标记结束。终态更新可以使用已预留空间；不能通过删掉实际执行计划来凑额度。历史列表分页返回摘要，完整计划按单次检查加载。

## 幂等、暂停与重启

手动检查使用客户端 UUID。在读取当前状态或领取新租约之前查询已有同 UUID 记录；响应丢失后重试返回原记录，不再次发起请求。规则与 UUID 不匹配应冲突，不能复用他人的动作标识。

暂停、规则替换和显式取消在同一配置事务中结束相应执行记录并隔离旧所有者。暂停保留源扫描、窗口、游标与已见集合；规则查询被替换时取消旧执行并重新建立扫描，保留已见身份与通知。应用重启领取过期租约时，把旧执行记录标记为中断，再从已提交检查点开始下一轮。

一秒心跳负责及时发现暂停/取消并丢弃排队或正在等待的网络 future。心跳 future 与页面循环并行推进，不能在页面循环持有存储锁时停下页面循环再同步等待心跳，否则会在同一存储互斥锁上死锁。进程被强杀时依赖持久租约超时接管，不假设析构函数一定执行。调度句柄全部释放时取消网络工作，避免任务持有自身句柄造成生命周期循环。

429 的持久重试时间不能被手动检查或重启绕过。权限/永久条件错误保留为需处理状态；一个源失败不清空其他源的成功水位。存储额度不足应等待配置或资源变化，不能不断创建失败记录并重复请求供应商。

## 接线与界面

`BibShared` 持有共享存储和单一调度句柄。调度必须使用已经注入完成的 gateway 与 discovery sessions；构造测试 bundle 时不得先启动真实默认来源。只有已启用规则或明确手动检查才允许网络执行。HTTP 与原生路由共用同一服务，鉴权与 no-store 策略沿用现有文献 API。

规则界面从当前有效发现请求创建，显示来源、周期、预算、窗口/重放语义和是否启用。库内收件箱展示新增匹配、来源与实际执行信息；失败、等待额度、未遍历完成和成功无新增分别显示。关闭界面不会取消持久后台任务，暂停/取消使用明确动作。

通知导入建立独立发现会话，按经过验证的 DOI/PMID/来源原生标识重新取得元数据，再复用已有预览/确认及目标集合冻结路径。无可靠标识的记录不凭标题自动对应到另一篇论文。通知删除不删除规范文献，也不清空已见身份。

## 验证

现有 21 项存储、7 项执行历史/扫描、执行器专项以及此前 14 项共享资源测试分别记录，不能相互代替完整产品验收。执行器已覆盖跨轮轮换、UUID 终态重试、429 手动检查等待、取消与 owner 释放、暂停、短原租约续租、多源错误隔离及注入网关。后续完整验收仍需覆盖：多源独立推进、重叠大于子窗口时不重复停留、跨预算与重启继续同一窗口、请求前预留与失败结算、失效游标重放、429 重启等待、全局成功判定、手动 UUID 响应丢失、运行中暂停/取消、租约接管及实际进程中断。随后覆盖鉴权 API、浏览器、模拟桥接与实际 Linux 原生完整工作流，再做阶段隔离与最终 P5 提交。

当前执行器一次轮到一个来源的一页，按租约 epoch 轮换首个来源；即使每轮仅一页也不会固定饿死后续来源。它复用交互式来源的全局/每源许可与冷却，不另外创建连接池。调度服务已实现默认两条规则并发、到期候选在 LIMIT 前过滤暂停/等待/活跃所有者、宿主句柄释放时取消并结算。额度等待以失败前资源 epoch 持久保存，额度不变时不会重新请求；删除历史/通知和实际额度变化唤醒等待者，唤醒会在新领取时消费，避免循环立即重跑。API 确认和后台运行期限分别控制；本地服务验证不替代 GUI、跨进程强杀和真实来源兼容性验收。

真实进程增量：专用宿主使用真实规范 DB、鉴权 HTTP API 和调度器，来源页为确定性 fixture。SIGKILL 后约 30 秒越过已观测租约截止接管并续接同一游标；完整关闭后复制全部 DB 家族、校验字节并重开，保留执行历史、已读状态和已见身份，删除通知不复活。另以 SIGSTOP/SIGCONT 验证旧进程恢复时主动丢弃尚未超时的源请求，不能覆写新进程结果；跨进程额度等待/唤醒也通过。见 [进程恢复资格](benchmarks/literature-search-p5-subscription-recovery-linux.json)。这不代表真实供应商、硬件断电或实际原生 GUI 已全部验收。
