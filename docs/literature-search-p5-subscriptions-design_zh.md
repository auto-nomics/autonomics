## 来源时间语义

| 来源 | 可用依据 | 首版策略 |
| --- | --- | --- |
| PubMed | [官方指南的 Modification Date `[lr]`](https://pubmed.ncbi.nlm.nih.gov/help/#modification-date-lr) 表示已完成引用的最近修订；同指南支持 Create Date `[crdt]` | 原始检索式分组后 AND 一个由创建/修订日期 OR 组成的闭合日期窗口；按 UTC 日界限与重叠窗口重放。明确 LR 的覆盖限制，不宣称等同于所有后台索引变更 |
| Crossref | [官方日期过滤](https://www.crossref.org/documentation/retrieve-metadata/rest-api/rest-api-filters/)支持 `from-index-date` / `until-index-date`，包含发布者、Crossref 和第三方变更；[官方同步建议](https://www.crossref.org/documentation/retrieve-metadata/rest-api/tips-for-using-the-crossref-rest-api/)要求固定上下界并缩小长遍历窗口 | 保留原查询/过滤，增加闭合索引时间窗口；不得使用发表日期替代；一次未完成遍历持续使用同一计划与窗口 |
| OpenAlex | [官方同步说明](https://help.openalex.org/access/sync/)将 `from_updated_date` 列为付费计划能力，普通 key 不等于该权限 | 默认有界重放；只有明确配置并验证同步权限后才启用相应时间策略。403 保持失败状态，不静默删除日期条件 |
| arXiv / S2 | 当前通用发现契约没有已经验证的可靠更新时间窗口 | 有界重放，明确已扫描范围、未完成状态和游标。保存成功检查时间，不把它叫作“已覆盖更新水位” |

Crossref 来源兼容性已修正并验证，见 [来源资格](benchmarks/literature-search-p5-source-compat-linux.json)：[官方接口变更说明](https://community.crossref.org/t/changes-to-cursors-filtering-and-sorting-in-the-rest-api/16246)说明游标结果可变化，某些发表日期排序不能与游标组合。订阅不能继续依赖发表日期排序遍历；规划执行顺序、能力声明与契约测试应一起核对。时间过滤不是上游不可变快照，重叠窗口和本地去重仍是必要措施。

所有时间窗口由服务端建立并持久化；请求中保存原规则，执行记录中保存实际窗口与计划。已完成源可独立前移自己的水位，失败或未穷尽的源保持原水位；只有全部源成功才更新订阅的全局成功时间。页面预算不足时持久化检查点，下轮继续相同窗口，不把截断说成完成。过期游标需从该闭合窗口重放，已提交已见集合保留。

## 持久数据与原子性

沿用规范数据库和独立连接，不占用规范文献写入 actor。建议实现 `subscriptions.rs`、`subscription_store.rs` 与服务调度模块；API 和 GUI 在验证存储后接通。

| 数据 | 要求 |
| --- | --- |
| 订阅配置 | UUID、名称、版本、完整 DiscoveryRequest、来源策略、间隔、重叠/初始窗口、启用/暂停、每轮页数/记录数/时间预算、下一执行时间；修改用版本比较并隔离旧任务 |
| 每源状态 | 已完成水位、当前闭合窗口、原计划及指纹、供应商不透明游标、页面序号、检查点、最近错误/重试时间、覆盖说明；已完成和仅取得一批结果分开 |
| 运行所有权 | owner UUID、递增 epoch、租约截止与心跳；不同进程竞争必须在立即事务中领取。暂停、修改、删除或租约接管后，旧 owner 不能继续提交 |
| 已见身份 | 来源与原始记录身份保证重复页面/重启不重复通知；规范 DOI/PMID 等用于保守跨源识别。冲突 DOI、预印本/正式版和多重匹配沿用 P3 保守策略，不凭标题合并 |
| 库内收件箱 | 保存来源元数据、原规则版本、实际执行计划、获取时间、状态和身份冲突；只读/已读/删除动作独立于已见集合。删除通知不意味着忘记已见身份 |
| 资源预算 | 持久订阅数、已见身份数、通知数/载荷、单页序列化载荷及每轮执行预算；事务内核验多连接共同额度。超限保留已有数据与检查点，明确等待额度或用户处理 |

每个页面的已见集合、通知和检查点在同一立即事务提交，并验证配置版本、owner、epoch 与当前页面。已提交响应丢失时从持久检查点继续；提交前失败没有半页通知。失败重试、游标失效和进程接管均不得删除已见集合。通知发布不自动修改原文献，导入复用已有预览/确认路径。

同一源的后台订阅和交互式发现共享连接、限流、冷却与并发预算。调度默认有界，每轮网络等待纳入期限；429 保存 Retry-After，权限或永久条件错误需要用户处理，不在后台无限请求。新配置/暂停/继续与所有权变更原子衔接。取消等待不以清空数据库实现。

执行历史与单轮执行器已完成本地专项验证；自动调度、额度等待和 API 也已接通；GUI 已接通并验证协议闭环，进程接管/关闭数据库家族恢复已验证，实际原生验收仍待完成。具体事务、生命周期和验证边界见 [调度细化](literature-search-p5-scheduling-design_zh.md)和 [执行器资格](benchmarks/literature-search-p5-subscription-execution-linux.json)。

## API 与 GUI

文献发现界面提供订阅当前有效规则，展示发送到哪些来源及频率/预算；专业原生查询仍保留实际参数。库内收件箱与文献库、发现、快照独立，显示新增匹配、来源、最后成功时间、进行中窗口及失败。用户可以手动检查、暂停、恢复、修改、查看执行历史与预览导入。

创建规则时可选择是否启用定时检查；只有用户主动启用或手动检查才启动来源请求。默认只产生库内通知。页面上“无新增”只能表示一次已成功完成的扫描；失败、预算耗尽、游标过期与尚未穷尽分别显示。

## 必须验证的场景

- 创建/修改/暂停/恢复/删除与版本冲突；重开数据库保留规则、来源水位和下一执行时间。
- 两个独立连接/进程争抢同一租约；心跳、超时接管、旧 owner 迟到提交以及修改期间提交均被正确隔离。
- 页面提交与进程中断前后的通知/已见集合/检查点一致；重试已提交页不重复通知，不跳过未提交页。
- 闭合窗口与重叠区、迟到回填、同日边界、空结果、部分来源失败、预算截断、过期游标及恢复；不得用发表日期填补更新语义。
- 多源身份归并、冲突 DOI、相关版本、匿名/无强 ID 的来源身份、删除通知后再次重放、已见额度耗尽与手动释放通知额度。
- 429、Retry-After、权限错误、断网、整体期限、取消、重启后重试时间；固定客户端与响应预算。
- 浏览器与实际 Tauri 的规则创建到检查、收件箱、预览导入、暂停/重启恢复。模拟桥接仅做局部资格，不替代原生。

当前存储/执行基础（尚非产品闭环）：`subscriptions.rs`、`subscription_store.rs`、`subscription_store/pages.rs` 和 `subscription_plan.rs` 已实现规则版本、暂停保留检查点、独立连接租约竞争、过期接管及提交前再次核验所有权。操作时钟把连接等待和事务处理经过的时间计入过期检查；心跳不能在旧租约已过期后复活所有权。

每页的已见身份、库内通知、游标历史和检查点在同一立即事务提交。通知删除保留已见身份；后补 DOI 可丰富已见身份，安全桥接合并通知组，冲突 DOI 与预印本/正式版保留独立组及复核关系。组成员/通知贡献上限各 512，超限整页回滚。源错误、Retry-After 和过期游标的同计划重放亦可持久保存。资源额度按多连接共享的事务内计数核验；降额保留数据，仍可标记已读或删除通知。默认每库 128 规则、100k 已见记录、256MiB 已见逻辑载荷、10k 通知、128MiB 通知载荷、2MiB 单页/通知组，以及 100k 游标检查点；这些是逻辑载荷与记录预算，不是物理数据库硬配额。

已有 21 项独立存储工作流测试及 14 项发现资源执行测试通过；完整后端 416 项通过发生在最终经过时间检查与两个新增测试之前，不能视作当前全部源码的完整资格。后台单页执行入口与交互式发现共用同一全局/每源信号量及冷却；测试证明后台请求不能绕过交互式 arXiv 单槽或 Retry-After。详见 [存储基础资格](benchmarks/literature-search-p5-subscriptions-storage-linux.json)。这些均为本地测试，无实际供应商订阅或外部通知发送。

闭合窗口规划保留原请求硬条件。PubMed 使用完整 UTC 日，Crossref 使用完整 UTC 秒并明确披露索引时间升序遍历；已存在原生索引日期过滤的规则和单 DOI 检查不能被静默改宽或宣称更新水位，需在调度层选择有界重放。时间窗口参数及指纹由存储层按保存规则重新核验，不能提交一个未执行该时间限制的计划并前移水位。

尚需完成：持久整轮截止点与历史、预算调度及中断恢复服务、来源兼容性修正/真实 HTTP 契约、BibShared 接线、鉴权 API、GUI 规则/收件箱/导入、进程级崩溃/备份恢复与原生资格。所有来源成功的全局时间仍不由当前存储基础提前填写。完成完整验收后再形成 P5 阶段提交。

当前 GUI 的通知导入优先采用原来源标识；arXiv 明确版本不折叠为基础 ID，多个冲突 DOI 不随意择一。重新发现的候选必须包含同一规范标识才允许预览；客户端不把通知元数据直接提交为文献。目标集合在打开预览时冻结；原选择已不可用时阻止操作，不静默回退到默认库。此资格为本地浏览器/模拟桥接，不代表真实供应商或原生端已完成验收。

Crossref 最新/最早发表通过有边界的 offset 保持原排序；订阅索引窗口单独披露 indexed asc，并移除不再适用的 offset 提示。旧模式/失效供应商游标的后台重放保留冻结计划与已见集合，不会因为适配器原先标记 non-retryable 而永久阻塞。真实公开复核限于两个公共 DOI；全局来源可靠性、付费权限和原生/跨进程恢复仍需分别验证。

真实进程增量：专用宿主使用真实规范 DB、鉴权 HTTP API 和调度器，来源页为确定性 fixture。SIGKILL 后约 30 秒越过已观测租约截止接管并续接同一游标；完整关闭后复制全部 DB 家族、校验字节并重开，保留执行历史、已读状态和已见身份，删除通知不复活。另以 SIGSTOP/SIGCONT 验证旧进程恢复时主动丢弃尚未超时的源请求，不能覆写新进程结果；跨进程额度等待/唤醒也通过。见 [进程恢复资格](benchmarks/literature-search-p5-subscription-recovery-linux.json)。这不代表真实供应商、硬件断电或实际原生 GUI 已全部验收。
