## 已实现的独立存储

实现位于 `crates/bib-base/src/search_snapshots.rs`、`search_snapshot_exports.rs`。专用测试最初通过路径模块编译，现已改为测试库正式导出的模块；P4 入口基线在接线前单独归档。记录是保存时的完整副本，之后编辑、删除原文献或外部会话过期，不会改写它。

| 内容 | 当前约定 |
| --- | --- |
| 本地执行 | 原始请求、逐页请求与响应、文献副本、命中与片段、总数/游标、index generation、召回说明 |
| 外部发现 | 同一 sequence 的 session 与候选窗口，包含原始来源贡献、字段冲突、实际参数、翻译、来源状态和失败 |
| 时间与版本 | 执行开始/结束时间、保存时间、格式版本、查询契约版本、引擎/依赖指纹；混合记录固定模型、来源端点、digest、profile、inference、两个 generation |
| 覆盖说明 | `complete_matches`、`candidate_pool`、`obtained_candidates` 分开；保存完整已取得候选集合不等于全部来源已耗尽 |
| 幂等 | 客户端行动键与名称/查询/窗口意图绑定；同一行动返回原始记录，改变意图返回冲突；可在执行查询或访问过期来源之前查找已提交结果 |
| 默认预算 | 最多 1,000 个快照、每个序列化载荷 8MiB、总载荷 256MiB；降低预算保留现有记录，不自动逐出 |
| 写入 | 立即事务内重新读取持久预算并检查计数/实际载荷；两个独立连接不能同时绕过同一额度 |
| 列表 | 单调序号水位、库身份及最高记录 UUID 锚点；新插入不混入后续页，跨库或锚点变化要求重新分页 |
| 校验 | 载荷 SHA-256、长度、意图与覆盖说明；损坏载荷不能读取/导出，但按记录与已知校验值显式删除可释放额度 |

本地捕获拒绝不同查询、断裂游标链、跨 generation、重复命中、缺失或不匹配文献元数据。混合捕获要求模型 provenance 与各页实际 generation 一致。发现捕获拒绝 sequence 混用、遗漏请求来源、候选区间不一致和无来源贡献的记录。

## 冻结导出

三个格式都只使用保存的内容，不重新按 ID 读取当前库。JSON 是完整追溯包，不是假装多个 CSL 对象拼成一个 JSON 文档；RIS 和 BibTeX 是文献交换投影。

- JSON 保留原始换行、执行请求、版本、片段、来源与覆盖说明。
- RIS 对交换字段中的控制字符/换行做单行化，避免被解析为额外字段或记录；JSON 中的原始文字不受影响。
- BibTeX 对同一文件内的重复引用键增加稳定后缀，不覆盖不同文献。
- 导出有显式字节预算，超限返回错误，不截断为看似完整的文件。

一个确定的浮点评分反例曾导致合法快照在读回后导出时被误报校验失败。P5 为 `serde_json` 启用 `float_roundtrip`，验证 128 个评分样本逐位往返。该 Cargo 变更属于 P5，不能混入 P4 提交。

目前 20 项专用测试及严格 Clippy 通过，见 [存储资格记录](benchmarks/literature-search-p5-snapshot-storage-linux.json)。这些是存储、格式与本地执行测试，不是上游引用质量、API、GUI、完整进程崩溃或操作系统备份恢复资格。列表分支测试替换关闭夹具的 UUID 来模拟序号复用，不冒充实际文件备份演练。

`capture_library` 已提供未接线的服务端捕获函数：先按行动键查询已提交记录，再准备运行信息、执行实际分页并强制水合元数据。每页核验 generation、游标和完整载荷预算；分页间发生修改或执行取消时不发布部分记录。提交响应丢失后的重试不再次查询或要求模型在线。数量预算保留完整实际页面；剩余额度不足下一实际页面时停止，实际保存篇数可能少于上限，不伪造截断页或下一游标。四项捕获用例使用真实本地词法查询验证这些行为；末页不足页大小但总量可容纳时仍保存完整末页。

开发树回归：首次并发运行在 HTTP 维护用例的 8 秒等待处超时，原因尚未确定；单项复跑约 1.6 秒通过，未放宽等待阈值。随后完整串行回归 369 项通过、0 失败、0 忽略，包含原有 353 项与该轮已编译的 16 项快照测试。新增捕获函数后的当前 19 项专用测试单独通过；不把 369 写成 P4 独立阶段测试数量，也不声称完整串行轮已包含新增三项。日志和校验值见同一资格记录。

## 引文与推荐接入的已核对条件

本机已有 `semantic-scholar` SDK 的 `get_citations`、`get_references`、`recommendations`，Agent 的 `source_literature_citations` 节点也已调用前两者；产品接入应复用共同客户端与节流，不再生成互不协调的请求池。

[Semantic Scholar 官方说明](https://webflow.semanticscholar.org/product/api)当前给出的 API key 入门额度是跨端点 1 RPS；匿名请求共用服务额度，还可能被进一步限流。现有 SDK 的 clone 共享 1,050ms 请求起始间隔和冷却状态。真实额度会变化，服务仍须处理 429 和 Retry-After，不能把匿名共享池当作本应用配额。

[官方 Recommendations 文档](https://api.semanticscholar.org/api-docs/recommendations)区分推荐与引用，单篇推荐最多 500 条，默认来自 `recent` 池，另有 `all-cs`。现有 SDK 默认不传 `from`；首版至少必须标识为近期推荐，不能把默认结果说成全学科、全历史的相似论文全集，也不生成引用边。

引用/被引保留 API 原始 offset/next，来源方向分别为“种子引用目标”和“目标引用种子”。未识别/不可解析条目单独计数，不能丢弃后再用过滤后的长度推进游标。现有 SDK 的 `Paper.paper_id` 是非 nullable String、引用条目内的 Paper 也非 nullable，接入时须用本地响应夹具覆盖缺失/null 情形，决定明确的未解析表示；目前尚未声称真实上游验证通过。


## 快照产品接线与当前资格

`BibShared.search_snapshots` 在磁盘模式直接使用同一规范数据库；内存 bundle 独立持有临时存储。已接入 `/search/snapshots` 的创建、分页、只读读取、校验值删除、冻结导出，以及持久预算读取/设置。创建请求拒绝客户端结果行；128KiB 请求体上限与 100–120000ms 整次捕获期限独立约束输入和执行，支持既有请求取消。混合记录从服务实际状态取得模型、profile、推理参数和 generation，每页核验；查询或来源变化返回冲突，不拼接成新旧混合记录。发现捕获的 session 与候选在同一锁内取得；已提交动作可在原会话被删除后返回原始结果。

GUI 的本地查询与发现候选工具栏都有保存入口，固定某次操作的请求和行动键；响应丢失后重试复用同一行动。Snapshots 工作区展示时间、覆盖、来源失败、原始执行信息与冻结元数据，支持 RIS/BibTeX/JSON 导出及显式删除。源文件不被复制到快照；不以保存规则冒充固定结果。返回该工作区时刷新列表，列表与只读预览使用可取消请求。普通阅读器和 Agent 的其他工作区修改未纳入本阶段。

## 引文到导入的交接

列表内有规范 S2 身份的论文可进入 Review import；未解析条目没有该入口。新对话框使用既有 `useDiscovery` 创建独立的精确 lookup 会话，获取新的候选和指纹，目标固定为打开时选中的库或集合。用户先预览，确认前保留已有元数据/相关版本/冲突说明；提交只发送会话候选和指纹，不发送引文面板的文献元数据。冲突会清除旧预览、刷新候选，重新预览后才能确认。关闭对话框删除该独立会话，保留原发现工作区；确认后刷新库数据。

本地 HTTP 集成串联 graph → fresh exact discovery → preview → commit，证明已存在的人工标题与标签保留、无重复条目。浏览器与模拟桥接各增加 10 次导入会话请求，覆盖确认前禁用、已有记录预览、409 后重新预览及清理。原图中的引用边来自获取时的图数据；精确文献查找不会生成新的引用事实。真实上游覆盖和实际原生仍待阶段验收。
